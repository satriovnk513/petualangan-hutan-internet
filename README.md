# Petualangan Arif dan Safira di Hutan Internet

An interactive story game that helps primary school children practise media and information literacy. Players walk through fifteen everyday digital situations with Arif and Safira, choose what they would do, and see what happens next. The game is available in Indonesian and English.

**Live demo:** https://petualangan-hutan-internet.netlify.app/

## About the project

This project was developed as a submission for the UNESCO Youth Hackathon 2026.

It is not an official UNESCO product. It has not been endorsed or approved by UNESCO, and it is not affiliated with UNESCO in any way. The UNESCO name appears here only to describe the event the project was created for.

## Key features

- Five locations in the Internet Forest, each with three story situations, making fifteen decisions in total.
- Topics covered: protecting personal information, checking sources before believing a story, recognising content generated by AI, responding to unkind comments, and asking a trusted adult for help.
- Answer choices are shuffled every time a level starts or is replayed, so children cannot memorise the position of the correct answer.
- Feedback after every choice explains the consequence without blaming the child. The game always lets players continue.
- Badges and treasures collected across the map: Kunci Kewaspadaan, Kompas Kebenaran, Lensa Ketelitian, Perisai Kebaikan, and Mahkota Kebijaksanaan.
- A printable certificate once the adventure is complete.
- Full Indonesian and English translation with a language switch on every page.
- Progress is stored only in the browser on the player's own device. There are no accounts, no advertising, and no analytics.
- Keyboard navigation, visible focus states, screen reader labels, and support for reduced motion.

## Who it is for

- Primary school students in grades 4 to 6, roughly ages 9 to 12.
- Teachers who want a classroom activity, either on a projector or on student devices.
- Parents who want to learn alongside their child at home.
- Community groups, reading centres, and youth organisations running digital literacy sessions.

## Technology

- React 19 with React Router 7, using HashRouter so that every route works on static hosting.
- Vite 8 as the build tool.
- Plain CSS organised into design tokens, base styles, layout, game screens, hero, and certificate.
- Oxlint for linting.
- No UI framework, no CSS framework, and no runtime dependencies beyond React and the router.

## Running the project locally

You need Node.js 20 or newer and npm.

```bash
git clone <repository-url>
cd petualangan-hutan-internet
npm install
npm run dev
```

The development server prints a local address, normally http://localhost:5173.

## npm scripts

| Script | What it does |
| --- | --- |
| `npm run dev` | Starts the development server with hot reloading. |
| `npm run build` | Builds the production site into `dist/`. |
| `npm run preview` | Serves the production build locally so you can check it. |
| `npm run lint` | Runs Oxlint across the source. |
| `npm run deploy` | Builds the site and publishes it to GitHub Pages. Not used for Netlify. |

## Building for production

```bash
npm run build
```

The output goes into `dist/`. That folder is not committed to the repository.

The base path matters. `vite.config.js` defaults to a GitHub Pages subfolder, so when you build for a host that serves the site at the root of a domain, set the base explicitly:

```bash
VITE_BASE=/ npm run build
```

Netlify does this automatically through `netlify.toml`, so a normal Netlify build needs no extra step.

## Project structure

```
src/
  data/          All game content and translations
  pages/         One file per route
  components/    Reusable interface pieces
  context/       Game state and progress
  i18n/          Language switching
  hooks/         Sound, reduced motion, scroll behaviour
  utils/         Assets, storage, answer shuffling
  styles/        CSS, split by area
  assets/        Illustrations and backgrounds
public/          Files copied to the site root as they are
```

## Editing the quiz and the translations

All player facing text lives in three files. Nothing is hardcoded inside components.

| File | What it holds |
| --- | --- |
| `src/data/levels.js` | Every level, scenario, question, answer choice, feedback message, tip, badge, and treasure, in both languages. |
| `src/data/ui.js` | Buttons, navigation, labels, page titles, screen reader text, and other short interface strings. |
| `src/data/content.js` | Longer pages: home, teacher guide, parent guide, about, and privacy. |

`src/data/levels.js` is split into two parts. The first part is the game skeleton, holding level ids, scenario ids, choice ids, points, and which choice is the wisest. The second part holds the Indonesian and English wording. When you edit content, change the wording only.

Two rules matter when editing:

- Never decide the correct answer by position. The wisest choice is matched by `bestChoiceId` against `choice.id`, because answer order is shuffled at runtime. The shuffle itself lives in `src/utils/shuffle.js`.
- Never rename a scenario id or a choice id. Player progress is saved against those ids in the browser, so renaming one would erase saved progress.

Always update the Indonesian and English versions together so the two languages stay in step.

## Deploying to Netlify

`netlify.toml` is already in the repository and sets everything Netlify needs:

- Build command: `npm run build`
- Publish directory: `dist`
- Node.js version 20
- `VITE_BASE=/` so assets resolve at the root of the domain
- A redirect that sends unknown paths to `index.html`, so refreshing the browser on any route works
- Security headers and long lived caching for built assets

There are two ways to publish. Pick one.

### Option A — Drag and drop a build (no Git needed)

Fastest way to get a link, and the right choice for a one-off classroom build.

```bash
VITE_BASE=/ npm run build
```

Then open https://app.netlify.com/drop and drag the `dist` folder onto the page. To update an existing site instead of creating a new one, open that site in Netlify, go to **Deploys**, and drop the folder into the deploy area there.

The `VITE_BASE=/` part is not optional for this route. A plain `npm run build` targets the GitHub Pages subfolder, and a site built that way loads a blank page on Netlify because every asset resolves under `/petualangan-hutan-internet/`. Netlify only sets the variable for itself when it runs the build, which is why builds started on your own machine need it spelled out.

### Option B — Connect the Git repository (automatic deploys)

Better when the site will keep changing: every push republishes the site.

1. Commit the project and push it to a GitHub repository.
2. In Netlify choose **Add new site → Import an existing project**, then pick the repository.
3. Leave the build settings as Netlify suggests. It reads `netlify.toml`, so the command, publish directory, and base path are already correct.

After that, every push to `main` triggers a new deployment. No Netlify token or site id is stored in this repository.
